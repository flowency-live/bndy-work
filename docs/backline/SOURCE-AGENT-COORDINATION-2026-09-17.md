## Ownership

- Each source agent owns its source-local adapter, extraction, proposed definitions, fixtures/tests and handover. Source-specific work can proceed independently where evidence supports it.
- CTO owns generic runner, projection, identity/geography, admission, API/schema, registration, integration, costs and cross-source documentation. Report shared dependencies **on your source issue only**. CTO alone coordinates Backline #58 requests.
- AWSCLI executes reviewed deployments/investigations and supported conditional application-data changes. It does not code, waive policy, change tests or choose wider activation.
- Ops owns UI/consumer verification. The prepared qualified-count consumer is already implemented; publishing and verification remain separate.
- Claim exact files, isolated branch/base and issue/session; reconcile active claims. No source self-merge/deploy or duplicated engine inside adapters. A posted assignment does not start a worker.

## Admission and outcomes

Preserve Place/source bindings and do not select a wrong building to reduce holds.

Saved execution “receipts” are evidence, not a new canonical entity/service. Follow successor holds to terminal outcomes: enqueue, expiry and supersession are not recovery.

## Releases, cost and handover

All Lambda/infrastructure changes use SAM/CDK through CloudFormation, including small changes. No direct Lambda update, hotswap, sync or stale template. Preserve reduced resources, current parameters and unrelated deployed fixes. Application-data changes are exact supported conditional updates, not whole-record reseeds.

One shared September ceiling is $500 gross including accrued usage, not per source. Existing authorised Places/enrichment paths use reviewed bounded budgets; no unrelated provider/resource expansion or daily full-profile crawl. Small [skip ci] commits, focused tests, no Actions/full-suite campaign. No blanket replay/queue purge, source reset, national bootstrap or competing legacy writer. The specific retained-outcome metadata indexing order is not permission for canonical rehydration.

Post source-issue updates on claim, material progress/blocker, handover and at least every 30 minutes while actively executing. Include actual commit/tests, deployed evidence, coverage and exact next owner/action; do not imply background work. CTO maintains shared documentation.

Use bndy-work and resolve the current @bndy-work Project before native field edits. Retired bndy-ops issues and website JSON are not the board. Issue/body changes do not update Project fields. Preserve import markers. Keep raw captures, runtime identifiers and private operational evidence in private repositories.

Dated prompts and audits remain historical unless referenced by the current order. Do not resurrect old paused writers, source budgets or direct-function deployment mechanics.
